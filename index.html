Month-End Capacity

Challenge

A complex month-end batch was moved from on-premises to the cloud as-is. Running 200,000 growing to 300,000 scenarios sequentially, on a machine type that did not fit the workload, it took around 14 hours.

Approach

  • Split the independent scenarios into batches, each running on its own machine
  • Ran proofs of concept across machine types and scenario sizes to compare runtime and cost
  • Worked with the cloud provider to reserve the required machines for the client's month-end runs under their prepaid account, as the best-fit type was not available in the home region
  • Built an availability check with a pre-validated fallback machine type, so planned volume still runs if the primary cluster is unavailable

Outcome

Run time was reduced significantly, month-end runs became reliable, the process scales to 300,000 scenarios, and choosing the right machines cut cost by about 20%.

Challenge

When a customer wanted API access to their ITSM data, we ran a separate project and built bespoke APIs just for that customer. Each engagement took months before the customer could start using the data.

Approach

  • As the architect, defined the API strategy aligned to TM Forum Open API and MEF standards
  • Designed and built standard TM Forum Open APIs on API management platforms (Apigee, WSO2), replacing customer-specific API projects
  • Published them on an API portal where customers subscribe, onboard and test the APIs themselves
  • Covered operational domains such as inventory synchronisation, incident, change, event and problem management, in a standard format customers link into their own applications and ITSM tools

Outcome

Customers subscribe to the APIs themselves from the portal and, once approved, start using them within hours instead of waiting months for a dedicated project. The platform is featured in a TM Forum case study.
